# 对话旅程与交互

- Kind: experience
- Status: canonical design target
- Visual authority: [视觉与动效方向](./visual-art-direction.md)
- System authority: [对话式六维决策 Harness](./conversational-six-dimension-harness.md)

## Experience thesis

界面不是“聊天页套问卷”，也不是五步向导。它是一张持续展开的工作台：Agent 的话、问题卡、用户回答、阶段性理解和未来草图都留在同一条时间线上。用户既能快速点选，也能随时打断并用自己的话重写问题。

真正的拟人感来自对上一句的吸收和节奏选择，不来自头像、打字动画或每题一段“我懂你”。

## Information architecture

### Persistent shell

始终保留：

- 顶部：产品名、当前阶段的轻量文字状态、暂停/隐私入口；
- 主区：按时间排序的对话与可折叠成果；
- 底部：自由输入 composer、发送、附件与“先到这里”；
- 上下文入口：六维雷达、资料来源和当前版本，默认收起，不做 dashboard。

### Focus views

路线意向、三条普通一天、正式三路和三天试验可打开专注视图，因为它们需要比较和编辑；关闭后回到触发它们的对话位置。专注视图不创建第二条历史，也不隐藏生成依据。

## Journey

### 1. Landing and first contract

首屏只说明用户会得到什么：

> 我们会聊几轮。你可以点卡片，也可以直接告诉我。每一轮我都会把目前的理解交给你校准，最后一起打开三种可以试运行的生活。

同时可见：无需先注册、可随时跳过/暂停、不是心理测评或人生预测。主 CTA 是“开始说说”，次 CTA 是“先看看会发生什么”。

### 2. Optional material

用户可以上传简历、MBTI 报告或文字文件，也可粘贴一段内容。上传区明确：

- 可选，不上传不影响核心体验；
- 文件只作为线索，系统会让用户校准；
- 是否发送给第三方模型、保留多久、怎样删除；
- 文件中的指令不会被执行。

解析中不阻塞用户开始说话。解析失败允许继续、重试或删除，不把错误伪装成已理解。

### 3. Opening exchange

Agent 先吸收用户主动输入；若没有内容，以“为什么今天想开始”进入。第一微批次必须覆盖两个功能，但不固定措辞：为什么是现在、最近一次具体情境。

如果用户一上来写了长段经历，Interviewer 先判断其中已覆盖哪些提问目标；第一批可以只问 1–2 个真正缺少的澄清。宿主以 5–10 个有效目标和最多 10 道实际问题治理，不机械重问。

### 4. Question microbatch

一次显示 1–3 张紧凑问题卡，通常为 2–3 张；最后一个缺口或长回答后的澄清可以只有 1 张。每张卡只有一个决策目标，可以是：

- 单选：选项互斥且确实降低回答负担；
- 多选：说明可选数量和“都不是”；
- 排序/取舍：只在比较本身有意义时使用；
- 量尺：两端使用行为锚点，不将分数解释成人格；
- 场景回忆：提供短文本输入和“不确定/想不起来”；
- 开放文本：在卡片内回答，也可直接使用底部 composer。

所有问题都能跳过。敏感问题额外显示“为什么可能有用”和低暴露回答方式。不能把六维标签展示成考试章节。

### 5. Submission and folding

用户可以逐题保存草稿，批次提交后：

- 卡片折叠为一个或多个用户气泡；
- 保留问题的简短上下文，避免以后看不懂答案；
- 显示“来自问答卡”和编辑入口；
- 焦点移动到 Agent 承接消息，读屏播报不重复整张卡。

自由输入若与卡片冲突，以较新的明确表达为候选修订，先让用户确认，不暗自选边。

### 6. Between microbatches

Agent 可以输出 0–2 句承接：

- 内容反映：“你提到，真正让你累的不是任务量，而是一天被不断切碎。”
- 追问理由：“我想再分清：你要的是独处，还是能完整掌控一段时间。”

不得在这里展示完整雷达、长总结或身份判断。若用户明显想继续说，下一批卡片可以暂缓，composer 保持主位。

### 7. Wave end and insight bubble

处理满 5 个有效提问目标后，AI 可在 mission 完成时提议结束；实际第 10 题强制结束。Sensemaker 生成一张正式理解气泡：

- 你告诉我的；
- 我目前的理解；
- 还不确定；
- 雷达变化；
- 对路线的影响。

气泡下方提供：`准确`、`部分准确`、`不准确`，以及可选方向：`沿这里继续`、`换一个方向`、`先看暂定路线`、`先到这里`。反馈控件不得使用奖惩色彩或让“不准确”显得负面。

### 8. Radar bubble

雷达是一个轻量弹层或气泡，不是常驻仪表盘。它按六维列出状态和一条依据：

```text
动机 · grounded
你在两个具体场景里都把“完整做出一个东西”描述为有生命力。

关系 · declined
你暂时不想展开，这不会阻止我们继续。
```

不显示总分、完成率、进度环或与他人比较。点击某维可查看来源和撤回/纠正入口。

### 9. Next-wave choice

Interviewer 根据已校准理解提议下一波 mission。界面只向用户说明人话版本，例如：“下一轮我想看看，你在独立创造和与人协作时，哪一种普通节奏更像你真正能长期过的生活。”

用户可接受、改方向或结束。深挖波不标成“你还不够完整”，而说明它会改变哪个路线判断。最多两个深挖波，且总波数不超过五。

### 10. Provisional preview

用户任何时刻都可请求。系统展示已有路线种子、证据不足处和如果继续最值得知道什么。预览必须比正式三路更轻，不伪装成熟答案，也不能用“继续访谈才能解锁”制造焦虑。

### 11. Route intents

访谈因 mission 足够、用户预览/停止或第五波上限而结束后，先把当前“我们真正要设计的问题”作为一条可编辑句子交给用户接受或改写。提交时必须关联促成这句话的 active direct-user source；它不是模型在后台自认成立的总结。随后展示 3–5 张路线意向短卡：名字、核心生活变化、最真实的吸引与代价、证据状态。此时还没有任何路线被系统替用户接受。用户可以：

- 改名或改写；
- 合并相似意向；
- 删除完全不想认真考虑的方向；
- 添加一个模型漏掉的方向；
- 指出某个意向只是想象实验，也值得暂时保留。

用户明确接受恰好三个意向，六个 life-shape 轴都已填写，且每一对至少在两个标准化轴上不同并通过语义非换皮校验后，才进入普通一天。

### 12. Three ordinary days

每个路线先展示一个可浏览的普通工作日/学习日/照护日，而非戏剧性的成功日。桌面端可并列，手机端使用同权重分页或纵向折叠，默认不突出第一条。

每个普通一天包含：

- 起床到睡前的 4–6 个节奏节点；
- 主要工作/学习与反馈方式；
- 关系与责任；
- 环境、时间和资源；
- 能量高低点；
- 身份叙事；
- 明确的想象标记和仍需确认之处。

用户可对任一具体片段点“像我 / 不像我 / 不知道”，这会修订路线，不等同于选冠军。

### 13. Parallel lives

三条正式路线以平等结构呈现：三年形状、普通一天、吸引、成本与取舍、依据、未知、风险和三天试验。顺序无推荐含义，按钮文案统一为“试运行这一天/路线”。

比较模式只比较生活结构和机会成本，不输出综合分或“适配度”。

### 14. Three-day trial

试验页明确：要验证什么、今天最小动作、三日节奏、时间/金钱上限、现实反馈来源、观察信号、继续/调整/停止条件。用户可编辑、暂停、提前结束；提前结束后的复盘问题是“我们学到了什么”，不是“为什么没坚持”。

### 15. Bounded reflection and blueprint

计划后的 composer 只支持：解释依据、比较取舍、调整低风险试验、复盘新反馈、生成当前蓝图。新事实默认作为本轮备注，不静默改写历史；若要更新路线，触发显式修订流程。

聊天到达回合上限或偏离 scope 时，给出简短总结和返回入口，不用依赖性措辞挽留。

## Recovery states

### Refresh and resume

- 已提交的问题批次恢复相同 id、顺序和答案；
- 未提交草稿仅在用户同意的本地策略下恢复；
- 恢复时说明上次停在哪，不重新欢迎或重问；
- guest 即将过期时给保存、导出或删除选择。

### Edit old answer

编辑后展示受影响的理解/路线列表。用户可以立即重算或先继续编辑；旧版本保留审计引用但不再作为 active evidence。

### Model failure

- 问题生成失败：保留自由输入，允许重试或暂停；
- 波次理解失败：回答不丢失，不展示半成品洞察；
- 正式路线失败：展示已校准路线意向和未知，不把降级骨架冒充完整三路；
- 所有重试幂等，不重复问题、证据或计费事件。

### Safety boundary

明显急性危机时停止普通问答卡和未来路线生成，保留会话并展示现实支持边界。不得在安全提示后继续用游戏化庆祝或“再回答几题”。

## Accessibility and mobile

- 360px 宽度完成所有主路径；composer 不被软键盘遮挡；
- 触控目标至少 44×44 CSS px；
- 选择不只靠颜色，卡片状态有文本/图标；
- 新消息和异步状态使用克制 live region；
- 200% zoom 不裁切，长文本可折叠但不隐藏关键未知/风险；
- reduced motion 下取消逐条弹跳和大位移；
- 键盘可完成卡片、编辑、校准、路线比较和试验；
- 雷达有线性文本等价物，不能只用图形。

## Anti-patterns

- 顶部进度条写“画像 62%”；
- 一屏十题、提交后只换到下一屏；
- Agent 每题都说“谢谢你的真诚分享”；
- 用三个颜色暗示路线优劣；
- 卡片提交后无法看见或修改原回答；
- 自由输入成为“其他”小入口；
- 暂定预览被做成付费/完成度解锁；
- 雷达像企业 BI dashboard；
- 引入新聊天组件后出现大圆角、紫色渐变或与现有纸张系统冲突的气泡。
