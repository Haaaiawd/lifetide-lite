# 短波次访谈、即时理解与三条人生支线体验

- Kind: experience
- Status: shaping
- Product: 人生试运行

## 1. 体验意图

用户应在一次移动端友好的连续体验中完成四个动作：讲一点自己、立即校准系统理解、比较三条平行人生、把一条路线变成可撤回的三天试验。持续对话留在方案旁边，帮助解释和复盘，但不抢走主流程。

**已确认事实**

- 上传简历、MBTI 或其他材料完全可选。
- 首波为 3–5 个以模板为主的问题；后续每波为 3–5 个自适应问题。
- 每波后只生成一张即时理解纸条；纸条内部的事实依据、当前解释、仍不确定依次显露。用户对整张纸条标记“准确”“部分准确”“不准确”，再可选“沿这里继续”指定下一波方向。不同波次的纸条逐张累积。
- 最终呈现三条地位平等的三年人生：延续线、邻近转向线、释放型通配线；一条被选择的路线可进入三天试验。
- 前台没有人格画像或画像完成度仪表盘。

**体验判断**

- 主界面应像一段有结构的对话，而不是问卷后台，也不是无限聊天流。
- “沿这里继续”是导航意图，不等于该理解已被确认为事实；它可以与“准确 / 部分准确 / 不准确”中的任一校准结果组合。
- 三条路线先平行浏览再选择；默认展开顺序不能被描述成推荐顺序。

**已确定的实现边界**

- MVP 先价值后注册：guest 会话在服务端临时保存 24 小时；只有跨设备继续或延长保存时才请求账号。
- 原 Lifetide 中权利不清的背景资产不进入 MVP；流程与品牌不依赖这些素材。已登记 CC0 的 water、boat 和 landmark 只能作为次要、可替换点缀。

## 2. 用户与使用情境

核心用户是正在经历方向不清、阶段转换或重要选择的年轻成年人。典型情境包括通勤中分几次回答、夜间独处时连续探索、桌面端上传材料后转回手机继续，以及三天内快速记录现实反馈。

设计必须容纳：

- 用户只有模糊来意，无法先写出完整问题；
- 用户不愿上传或不愿回答某些敏感题；
- 用户会中断、刷新或隔天继续；guest 会话在同设备 24 小时内恢复，跨设备或延长保存需创建账号；
- 模型理解可能错，且纠错必须比重新讲一遍更容易；
- 用户可能把方案误读成预测或推荐，因此边界需在关键节点就地出现。

## 3. 信息架构

移动端一级结构保持最少：

1. **探索**：开始/继续波次、波后理解与生成入口；
2. **三种人生**：三路总览、路线详情、当前三天试验；
3. **对话**：围绕本人、理解、路线与试验的持续会话；
4. **我与数据**：材料、隐私同意、导出、删除、账号（若启用）。

首次使用按线性主路径推进，不要求用户理解导航。生成三路后再显露完整一级导航。桌面端可用侧栏；移动端用底部导航，输入法弹出时隐藏底栏并保留当前任务。

## 4. 端到端旅程

### 阶段 A：进入与定调

1. 落地页用一句话说明：“通过几轮短问答，看见三种未来，并试玩其中三天。”
2. 主按钮“开始试运行”；次按钮“继续上次探索”（仅在检测到可恢复进度时出现）。
3. 首次开始前，以短句说明 AI、数据用途、可选上传、可跳过/删除及非治疗/非预测边界；必须同意的条款与可选研究授权分开。
4. 询问“这次你为什么来？”可多选并支持自填，用于定调而不是给用户分类。

### 阶段 B：可选材料

- 用户可添加简历、MBTI/人格材料或其他相关材料，也可点“先不上传”。
- 每个文件独立显示上传、解析、可用、失败、删除状态；MBTI 可手动选择并注明“认同/部分认同/不太认同”。
- 上传期间不阻塞已满足输入条件的下一步；解析未完成时明确说明首波不会假装读过材料。

### 阶段 C：首波问题

- 进入前说明“这一波有 3–5 个问题，答完立刻给你看我的当前理解”。
- 一屏一题。以单选、多选、短量表等模板题为主，始终允许“其他”或自由补充。
- 固定提供“跳过”；敏感题补充“不想谈这个”。选择后直接进入下一题或由用户点“下一题”，不能用模糊自动跳转造成误答。
- 顶部只显示“本波第 n 题”和可退出入口，不显示人格完成百分比。

### 阶段 D：波后即时理解

1. 回答提交后进入“正在整理这一波”状态，保留已答摘要和离开选项。
2. 本波只生成一张完整纸条。纸条进入后，内部三段依次显露：
   - **你告诉我的**：一至两条有直接依据的观察；
   - **我目前的理解**：唯一一条可纠正的暂定解释；
   - **还不确定**：最可能改变该解释或未来路线的一处未知。
3. 三段出现完成后，整张纸条只提供一组互斥校准“准确”“部分准确”“不准确”，另提供可与任一校准组合的“沿这里继续”。
4. “部分准确/不准确”展开可选短输入：“哪里需要改？”；允许不输入原因直接提交。
5. 反馈成功后就地更新状态。受影响的解释显示“已根据你的反馈撤回/待重看”，不静默改写历史。
6. 校准完成后提供“继续下一波”“用当前理解生成三种人生”（满足停止条件时）和“先停在这里”。下一波完成后，新纸条加入历史栈。

### 阶段 E：后续自适应波次

- 每波仍为 3–5 题；开头用一句话说明本波为什么问，例如“你希望沿工作中的能量感继续，我会确认两段具体经历”。
- 问题来源优先级：用户的“沿这里继续” → 会改变未来方案的纠正/冲突 → 关键未知 → 补充具体经历。
- 不重复已确认问题，不因上传了 MBTI 就围绕类型追问，不强迫用户展开明确跳过的敏感主题。
- 每波重复“作答—整理—气泡校准—继续/生成/暂停”，直到满足产品定义中的停止规则。

### 阶段 F：生成与比较三种人生

1. 生成前用确认页列出“将使用的已确认内容”“仍保留的未知”及三路不是预测/排名的说明。
2. 生成中分别显示三张中性占位卡；失败时保留当前理解，不让用户重答。
3. 结果页先显示三条等宽/等高入口卡：延续线、邻近转向线、释放型通配线。移动端横向切换必须同时有分页标签和“第几条”文本，不能只靠滑动。
4. 三条使用同一信息层级：三年主张、普通一天、关键阶段、所得/代价、现实约束、依据与未知、三天可试玩切片。
5. 不展示总分、皇冠、“最适合你”或默认高亮。系统可解释差异，但不代选。
6. 用户可收藏对比、回到某条理解继续补充，或选择任一路线“试玩三天”。选路文案明确：“这是先验证，不是最终决定。”

### 阶段 G：三天可逆试验

- 建立页把路线压缩成一个三天内可执行的真实切片：想验证的问题、每天最小动作、时间/金钱/他人参与边界、停止条件、记录提示。
- 用户确认或编辑动作后开始；不得默认安排不可逆、高成本或替用户对外执行的事项。
- 试验主页显示“第 1/2/3 天”、今天动作、简短记录、暂停、修改、退出和换路线。
- 每日记录允许文本与低负担选项：发生了什么、感受/阻力、与预期不同之处。未记录不惩罚、不制造断签。
- 第三天后进入复盘：支持这条路线的证据、反对证据、新未知、下一步（继续验证/修改/换线/停止）。不宣告路线被证明正确。

### 阶段 H：有边界持续对话

- 对话入口与三路/试验并存，可从某个理解气泡、路线段落或试验记录带上下文发起。
- 允许讨论自我理解、学业职业与生活选择、关系、习惯行动、路线解释和试验复盘。
- 对话引用记忆时用“根据你之前说的……”并允许纠正；聊天中新信息默认是临时上下文，涉及长期事实时邀请用户确认。
- 对无关通用代劳，简短说明边界并拉回用户当前人生问题；对危机、诊断或高风险内容不假装专业处置，按安全策略展示支持与紧急资源指引。

## 5. UI 状态与转移

| 场景 | 必备状态 | 主操作与转移 |
| --- | --- | --- |
| 落地/恢复 | 首次、可恢复、恢复失败 | 开始；恢复；失败时保留本地数据并重试/重新开始 |
| 同意 | 未选择、已同意、拒绝必要项、撤回 | 继续；拒绝时解释不可用功能；撤回后停止处理 |
| 材料 | 空、选择中、上传中、解析中、可用、部分可用、失败、已删除 | 添加/跳过；逐文件重试或删除；不阻塞无材料开始 |
| 波次 | 未开始、作答中、已答、跳过、提交中、提交失败、已暂停 | 下一题；失败保留输入；暂停后回到明确断点 |
| 整理 | 排队、流式生成、完成、超时、生成失败 | 继续等待/离开；超时可重试；不重复提交回答 |
| 理解气泡 | 待出现、已出现、反馈中、准确、部分、不准确、继续方向、反馈失败 | 标记/补充；失败就地重试且保留文字 |
| 波次决策 | 应继续、可生成、证据不足、用户暂停、安全停止 | 下一波；生成；说明缺口；保存退出；安全引导 |
| 三路生成 | 生成前确认、生成中、部分成功、完成、失败、过期 | 生成；单路重试；保留成功路线；证据变化后提示重生成 |
| 三路浏览 | 总览、路线详情、对比、无方案 | 切换路线；回到理解；选择试验；无方案回探索 |
| 试验 | 草稿、待确认、进行中、当日未记/已记、暂停、修改、退出、完成、复盘 | 开始/记录/暂停/编辑/换线/复盘 |
| 对话 | 空会话、发送中、流式回复、失败、越界、历史不可用 | 发送/停止生成/重试/新会话；越界时返回可支持范围 |
| 数据 | 正常、导出准备、导出失败、删除确认、删除处理中、删除完成 | 导出/重试；二次确认删除；展示实际影响范围 |

全局规则：任何异步操作都提供进行中、成功、失败和可恢复路径；刷新不得重复扣次数或重复创建对象；离线时可查看已缓存内容和未发送草稿，但需明确哪些尚未同步。账号与跨设备状态在相关决策完成前不得伪装为已支持。

## 6. 内容、视觉与无障碍

### 内容语气

- 像克制、好奇的同行者，不像测评师、治疗师或预言者。
- 解释使用概率和边界语言：“我目前的理解”“这可能意味着”；事实使用来源语言：“你在上一波提到”。
- 错误时直接承认：“这条理解不对，我会撤回并调整后续问题。”
- 问题一次只问一件事，选项包含用户不接受预设的出口。

### 视觉

- 视觉基线为 Soft Editorial Neo-Brutalism：off-white 细密浅方格纸、ink 墨色、主导 cobalt 强调色、2px 边框、3–4px 硬偏移阴影与 0–4px 圆角；绿色只表达成功、完成或可继续等语义状态，不作为装饰或路线配色。
- 关键陈述与洞察 claim 使用有编辑感的中文衬线体，控件、标签和正文使用高可读无衬线体；移动端减少并列卡片与装饰密度，保留清晰留白和单一主动作。
- 跨波次累积的即时理解纸条栈是探索页主骨架和产品视觉签名；每波一张，纸条内部三段依次显露。问题、理解和路线不能形成后台仪表盘观感。
- 事实、解释、未知不能仅靠颜色区分，必须有文本标签/图标和足够对比度。
- 三路卡片使用同尺寸、同密度、同按钮文案；不以颜色、阴影、位置或动效传达优劣。
- 动效只用于消息顺序出现和状态过渡；遵循减少动态效果设置，关闭动效不影响内容与操作。
- 明确拒绝高饱和大色块、多强调色、夸张贴纸堆叠的通用吵闹新粗野主义，以及 dashboard、儿童风和 AI 紫色渐变模板。neobrutalism.com／RetroUI 的 Radix registry 是主要组件来源，neobrutalism.dev 仅作次要实现参考；registry 组件必须按本产品 token 和密度改造。

### 响应式与可访问性

- 以单手竖屏为首要布局；触控目标、固定操作区和输入框避开安全区与软键盘。
- 桌面端限制正文行宽，不把移动卡片粗暴拉满；三路可并列对比。
- 所有操作可用键盘完成，焦点顺序与视觉顺序一致；流式新内容不抢焦点，并通过适当 live region 通知。
- 表单有显式标签、错误与修复建议；选择状态不只用颜色；支持浏览器缩放和系统字体放大。
- 用户输入与模型输出按纯文本安全渲染；外链和下载明确标识。

## 7. 错误、空状态与恢复

- **无材料**：说明“不上传也可以开始”，不展示警告式空白。
- **材料无法解析**：指出具体文件和原因；允许删除、重试或用文字概述，其他文件继续可用。
- **回答提交失败**：保留选择和草稿，不跳到下一题；重试必须幂等。
- **模型超时/断流**：保留已完成气泡，标记未完成项；允许从断点重试而非重跑整波。
- **理解全部被否定**：感谢纠正，撤回相关解释；下一波从用户补充或最小事实重新开始，不争辩。
- **没有足够证据生成**：具体说明缺少哪类会改变方案的信息，提供继续一波或暂停；不以“完成度低”羞辱用户。
- **仅部分路线生成**：已生成路线保持可读，失败路线原位重试；三条未齐前不引导选“赢家”。
- **进度冲突**：展示设备/时间和差异，默认不静默覆盖；账号策略确定后补充合并规则。
- **删除材料/记忆**：展示将受影响的理解、路线和对话上下文；完成后对派生内容重算、降级或标记失据。
- **安全边界**：停止常规生成，使用经审核的明确文案与适合地区的求助指引；不把高风险内容继续包装成人生试运行。

## 8. 可用性与验收验证

不先发明通过率。首轮建立基线，阈值由研究文档另行确认。至少验证以下任务与可观察结果：

1. **无上传首用**：用户能理解上传可选，完成首波并找到第一次气泡反馈。
2. **纠错闭环**：用户能把一条解释标为部分/不准确、补充原因，并看见该解释被撤回或降级。
3. **继续方向**：用户能预测“沿这里继续”的影响，下一波确实围绕该方向且不重复原题。
4. **事实边界**：用户能区分“你告诉我的 / 我目前的理解 / 还不确定”。
5. **三路平权**：用户能描述三路差异与代价，不把版式或文案误读为 AI 推荐；视觉不得被识别成 dashboard、儿童风、AI 紫色模板或吵闹多彩的通用新粗野主义。
6. **三天可逆**：用户能创建、修改、暂停和退出试验，并知道选择不等于长期承诺。
7. **中断恢复**：在题目、整理、气泡反馈、路线生成和每日记录中刷新/离线后，已输入内容不丢且不重复创建。
8. **边界对话**：相关问题得到带上下文回答；无关代劳与高风险请求触发正确边界。
9. **移动与无障碍**：常见窄屏、软键盘、字体放大、键盘导航、读屏和减少动效条件下可完成主路径。
10. **数据控制**：用户能找到材料删除、数据导出与撤回入口，并理解操作影响。

埋点应记录流程状态和操作结果，避免采集回答正文；研究记录将“用户说喜欢”与“实际能完成/能正确理解”分开。任何把解释伪装成事实、把一路暗示为正确答案、删除后仍引用原证据的情况均为阻断发布的问题。
